# 旁白与案例改写

## 叙事目标

把案例材料改写为可听、可视、可推进的故事，不做逐段复述，也不把全部吸引力押在一次大揭晓上。

当前默认采用“一个主问题 + 一组接力问题 + 连续叙事动作”的结构：

- **主问题**负责统领全片，例如“一个久经沙场的销售，为什么会输给看起来更弱的对手？”
- **接力问题**负责留住观众。每回答一层，立刻把注意力交给下一层。
- **叙事动作**负责推进状态。人物做了什么、局面发生了什么变化、代价增加了多少，必须可被听见和看见。

观众持续观看，通常不是因为答案一直被藏着，而是因为旧问题刚得到回报，新问题已经打开。

## 标题与旁白同期创作

标题是叙事承诺，不是分镜阶段补上的装饰。冷开场、主问题和结尾诊断稳定后，在写旁白的同一编辑步骤中选定标题，并把最终版本写入项目根目录的 `title.txt`。

- `title.txt` 只保留一行最终标题，不写“标题：”、备选项、Markdown、解释文字或手工换行。视觉换行由封面渲染器处理。
- 标题优先表达冲突、关键问题或反常结果，让观众立刻知道“为什么值得看”。避免“某某案例分析”“销售管理启示”等泛标题。
- 标题中的人物、时间、数字、结果和因果必须有材料或案例模型依据。不得为了点击率虚构事实、放大情绪或承诺正文没有回答的问题。
- 标题与固定栏目开场后的冷开场必须指向同一个主问题；如果改标题导致叙事承诺变化，应同步复核旁白，而不是只改封面。
- 可以在编辑过程中比较多个候选，但项目文件只保存选定的最终标题。悬念依赖揭晓时，标题不提前泄露全部答案。

分镜构建时，`rich_storyboard.json` 的 `cover.title` 逐字复制 `title.txt`。分镜阶段只决定排版、换行和持续 unit，不重新创作标题。

## 销售案例的前置模型

新写或大幅重构销售案例时，不从材料摘要直接起草旁白。先按 `case-story-model.md` 建立：

1. **客户客观真相：** 问题怎样积累、何时形成损失、什么事件触发改变、组织怎样在三类竞争选项中作出选择。
2. **客户披露路径：** 不同角色在信任、政治安全、权限和互动相关性的限制下，什么时候愿意分享公开、运营、组织、真实意图和个人需求。
3. **销售认知版本：** 销售和团队当时掌握什么，哪些是事实、客户表述、推断、假设、过时信息和未知。

外部供应商、客户内部方案和不采取行动是三类竞争。制度、利益冲突、风险、信任和个人偏好改变这三类选项的权重。

旁白负责安排信息的揭示顺序，不能改变案例模型中的因果事实。悬念来自销售版本与客户真相之间逐步缩小的信息差。

## 销售案例的双线骨架

销售和销售管理案例可以在通用问题接力结构中嵌入下面八步：

1. **后果或异常。** 先展示一个场面上可观察到的意外结果或无法用表面信息解释的动作。这里只呈现主角或观众能直接看见的事实，不提前揭示客户内部的损失、动机或决策过程。
2. **主问题。** 提出“客户为什么这样决定”或“销售究竟漏掉了什么”。
3. **问题积累与触发。** 销售出场之前，只允许揭示“触发场面上可见的事实”：冲突现场本身、当事人的公开说法和摆在桌面上的表面数字。机制类真相——问题怎样积累、内部错配、组织原因——必须扣住销售的互动事件（盘库、走访、对质、试点）逐层揭示，不能在销售出场前由旁白一次性讲完。判断标准：删掉销售的某次互动后，观众是否仍然知道对应机制？如果是，说明该信息被提前倾倒了。
4. **销售进入与第一版故事。** 交代线索来源、销售风格、初始假设以及他为什么相信这套解释。
5. **互动与逐级披露。** 每轮接触同时改变信任、信息、参与者立场或三类竞争权重。
6. **认知修正与边界升级。** 新参与者、组织政治、人员变化或外部事件，使旧信息失效并迫使销售更新故事。
7. **决定与结果清账。** 揭晓客户选择外部供应商、内部方案或不采取行动中的哪一类，以及具体选择了我方、竞品、某个内部方案或哪种搁置方式，并交代各方得失。
8. **真相合拢与诊断。** 完整还原客户问题链、决策网络、披露理由和销售误判，回答主问题。

前段可以主要跟随销售视角，但必须提前放置公平线索。销售赢单后才知道的内部事实适合在结尾合拢；销售始终无法确认的内容继续标为未知。

## 默认骨架：问题接力式旁白

4–7 分钟案例优先使用下面的九段骨架。素材不足时可以合并相邻段，但不能让中段退化成连续背景说明。

1. **冷开场。** 固定栏目开场后，用 1–2 句话呈现一个反常识的结果、矛盾或悬念画面，只负责让观众停下来。冷开场不交代背景、不介绍人物、不解释原因，全部信息指向一个疑问：”怎么会这样？”它对应样片中”反常识承诺”的功能（样片 0:00–0:34）。冷开场的判断标准：删掉它之后，观众是否少了一个”非看不可”的理由？如果是，它就是必要的。
2. **异常现场与人物锚点。** 进入冲突之前或冲突之中，用 1–2 句交代核心人物的身份和关系：他是谁、做什么、和谁处在什么关系里（例如”做了八年南岭饮品经销的赵海”）。锚点句必须贴着动作走，不允许退化成一段独立的背景介绍；随后立即给出具体动作、数字和风险，展开冷开场中的异常。没有人物锚点直接抛出人名属于缺陷。
3. **主问题。** 在前 20–45 秒内，把观众心里的疑问说清楚。问题必须指向因果，不只问结果。冷开场制造的悬念在这里收束为一个明确的问句。
4. **能力或常态证明。** 只补充能抬高预期的背景：主角为什么本来应该赢，原有方法为什么过去有效。
5. **竞争与决策的逐步浮现。** 客户面前的选择——外部供应商、内部方案、不采取行动——必须通过主角的互动场景逐步被观众看见，每一条路径的出现都要绑定一个具体的动作、对话或发现。旁白不能以全知视角一次性列出客户的所有选项和权重。判断标准：如果删掉主角的某次互动，观众是否仍然知道这条路径存在？如果是，说明信息被提前倾倒了。
6. **机制进入行动。** 用一次选择、一次交锋、一组数字或一句短引语解释机制，避免停下来上课。
7. **边界升级。** 冲突至少升级一次：从价格到信任、从客户到内部、从业务到组织政治，或从局部选择到制度约束。
8. **结果清账。** 先交代谁得到什么、谁失去什么、数字如何变化，再提炼意义。
9. **系统升维与诊断。** 回答主问题，把个案连接到可迁移的判断，最后用一个前文已经出现的意象闭环。

### 每个 beat 的五项合同

每个段落先写成一张 beat 卡，再扩成旁白：

```text
状态变化：这一段结束后，局面和上一段有什么不同？
证据锚点：用哪个动作、数字、物件或短引语证明？
当前问题：观众此刻最想知道什么？
交接句：这一段怎样把注意力交给下一段？
画面动作：这一段播出时，观众在屏幕上看见什么变化？
```

如果一段只有知识、评价或背景，没有状态变化，它通常应该被删掉、后移，或改写成行动。“画面动作”写的是可渲染的视觉事件（数字滚动、关系图展开、人物对话、证据指向、场景切换），不是“配一张相关的图”。

### 叙事质感：分析语言必须翻译成故事语言

案例模型（`case-story-model.md`）的分析框架只服务于建模，不允许直接进入口播。以下模型术语出现在 `narration.txt` 中即为缺陷：

| 模型术语 | 口播中的替代写法 |
| --- | --- |
| 竞争空间 / 三类竞争选项 | 让主角在互动中撞见每条路：”赵海问完价格才知道，对面柜台已经开始清库存了”；旁白不能以全知视角一次性列出客户面前的所有选择 |
| 披露层级 / L0–L3 | 用行为写出来：“他把仓库的账给她看了，但每天的销量表还锁在抽屉里” |
| 决策网络 | 写谁握着什么：“退不退货，赵海一个人说了不算，总部攥着费用，方琪只能在中间递方案” |
| 信念账本 / 假设区 | 写人物的判断动作：“她没有接受这个说法，先把它记成一个待验证的猜测” |
| 认知更新 / 问题定义 | 写发现瞬间：“盘完库她才明白，问题根本不在政策上” |

配套要求：

- 每个 beat 至少一个具体可感细节：一次动作、一件实物、一句原话或一个场景。连续两段没有任何可感细节，说明写作滑回了报告腔。
- 关键转折优先让人物动作或原话承载，旁白负责连接，不负责总结陈词。
- 抽象名词连用（“沟通由立场冲突推进到运营现场”）应改写成人做了什么（“她约他第二天去仓库，把库存一箱一箱看完”）。

### 问题接力规则

- 全片只保留一个主问题；局部问题一次只突出一个。
- 回答旧问题时，同时打开下一问题。不要回答完再另起一段硬造悬念。
- 每 20–45 秒至少兑现一次局部回报：一个答案、一次反转、一个新数字或一次关系变化。
- 连续 45–60 秒没有状态变化，说明背景过长或解释脱离行动。
- 设问后必须推进。不能用连续问句代替证据和因果。
- 背景只有在改变观众预期时才保留，例如证明主角很强、证明旧方法长期有效、证明某个限制无法绕开。

## 揭晓位置：按悬念引擎选择

`70–75%` 只适用于“单一答案型”案例，不再作为所有案例的通用规则。

| 悬念模式 | 观众追问 | 信息位置 |
| --- | --- | --- |
| 结果谜题 | 真正机会或真相是什么？ | 关键答案可在 65–75% 揭晓，前面埋齐因果伏笔 |
| 过程谜题 | 已知结果，究竟怎么发生？ | 异常或结果在前 5–15% 给出；机制在 45–70% 逐层兑现 |
| 决策困境 | 换成我会怎么选？ | 选项和代价在中段通过主角的互动逐步浮现；决定通常在 60–75% 揭晓 |
| 观众先知 | 角色何时发现观众已知的真相？ | 底牌在开头给出；发现和代价留到 60–80% |
| 性格悲剧 | 强项会怎样反噬主角？ | 失败可以开头预告；真正败因在结尾诊断 |

先写清楚“观众到底在等哪个答案”，再决定隐藏什么。不要为了反转而隐藏理解故事所需的前提。

## 中文口播与节奏

- 使用自然口语和短句，一句表达一个完整想法。
- 每个 TTS 单元优先控制在 8–16 个汉字，通常不超过约 20 字。
- 语速以约 330 字/分钟为基准。先优化信息交接，再考虑加速。
- 每 20–40 秒安排一个可记忆锚点：具体数字、动作、物件、人物原话或视觉意象。
- 允许少量“问题是”“为什么”“接下来”等口语转轴，但不能依赖“没错”“万万没想到”等口癖维持兴奋。
- 事实段和解释段交替出现。解释必须紧跟一个已经发生的动作，或直接引出下一次行动。
- 避免原始英文词混入中文句子；产品名、公司名、固定术语和关键原话除外。
- 避免 `不是……而是……` 及近似结构，改成直接判断、因果关系或两个短句。
- 每个空行分隔的段落保持一个声音；不要为了换声把同一完整意思拆开。
- 人类可读的 `narration.txt`、屏幕字幕和归一化后的 TTS 文本中，`CEO`、`CIO`、`CRM` 等英文缩写保持连写。

## 信息保真

- 删场景不删因果环节。任何关键选择都要能追溯到前文条件。
- 数字零改动；不新增事实；不提高源材料中的情绪强度。
- 销售的推断和假设必须归因给人物或团队，不能由旁白冒充客观事实。
- 客户组织信息、真实意图和个人需求只能在对应披露事件之后进入销售视角；提前出现时只能作为读者先知模式中的明确全知信息。
- 关键转折优先由人物动作或短引语承载。通常保留约三种不同立场的声音，避免全片只有叙述者解释。
- 保留“可能”“大概率”“往往”等不确定性措辞。
- 观点必须在结果清账之后出现，不能先讲道理，再让故事替观点作证。

## 时长预算

- 经验语速约为每分钟 330 个中文字符，包含自然停顿。
- 先通过旁白篇幅接近目标时长，再做小幅语速调整。
- 片头片尾约占 60 字，应从正文预算中扣除。
- 5–6 分钟通常能容纳一条完整的接力问题链。
- 8–12 分钟只适合拥有至少三次接力问题换挡、两次冲突边界升级和一次系统升维的材料；本项目默认仍为 4–7 分钟。

## 改写顺序

1. 销售案例先确认 `case_model.json` 或完成客户真相、披露路径和销售认知的等价核验。
2. 用一句话写出主问题。
3. 用一句话写出结尾诊断，确认它有源材料或案例模型依据。
4. 选择结果谜题、过程谜题、决策困境、观众先知或性格悲剧等揭晓模式。
5. 列出 7–10 张 beat 卡，先写状态变化和交接问题。
6. 把数字、短引语、关键动作和公平线索分配到 beat，避免集中堆在一段。
7. 先写冷开场、异常现场和结尾闭环，再填中段因果链。
8. 根据主问题、冷开场和结尾诊断选定最终标题，写入一行 `title.txt`。
9. 压缩背景，确认每段都承担叙事动作。
10. 同时完成标题事实与吸引力、标题和冷开场一致性、自然口播、禁用句式、缩写空格和数字读法复核。

## 写作检查

- 固定栏目开场后，冷开场是否在 1–2 句内制造了一个"怎么会这样"的悬念？冷开场是否不含背景介绍、人物履历或原因解释？
- `title.txt` 是否只有一行最终标题？标题是否提出冲突、问题或反常结果，并由材料和正文支持？
- 标题与冷开场是否承诺同一个主问题，且没有泛化“案例分析”、夸张失实或提前泄露全部答案？
- 冷开场之后，异常现场是否展开了冲突细节，并在 1–2 句内给出人物身份与关系锚点？
- 前 20–45 秒内，主问题是否已经清楚？主问题是否收束了冷开场制造的悬念？
- 段落揭示顺序是否与 `case_model.json` 的 `revealPlan` 一致？机制类真相是否都扣在销售互动事件之后？
- 是否存在模型术语直出（竞争空间、披露层级、决策网络、信念账本、认知更新等）？
- 每个 beat 是否至少有一个可感细节（动作、实物、原话或场景）？
- 当前悬念模式和揭晓位置是否匹配？
- 每个段落结束时，局面是否发生变化？
- 每段是否有动作、数字、物件或短引语作为证据？
- 回答一个问题时，是否自然交接到下一问题？
- 是否存在连续 45–60 秒纯背景或纯解释？
- 旁白中出现的每一条结论性信息（客户的选择、内部状况、竞争格局、决策权分布），是否都绑定了主角参与的具体场景（一次对话、一次走访、一次观察）？没有场景支撑的结论性陈述属于缺陷。
- 客户问题积累、触发事件、竞争格局和决策权分布，是否都通过主角参与的互动场景被观众看见？旁白是否只在主角获得信息之后才向观众揭示？
- 销售知道每条关键信息的时点，是否符合客户披露层级和信任变化？
- 销售版本是否区分事实、客户表述、推断、假设、过时信息和未知？
- 销售的认知是否因互动而更新，旧信息失效时是否被明确表现？
- 结果是否先清账，观点是否后出现？
- 结尾是否回答开头主问题，并回收一个前文意象？
- 年份、金额、比例、区间是否可被 TTS 明确归一化？
- 是否完成自然口语、禁用对比句式、缩写空格和数字读法风险复核？
