# 旁白与案例改写

## 叙事目标

把案例材料改写为可听、可视、可推进的故事，不做逐段复述。常用骨架为：悬念、背景、矛盾升级、关键选择、结果或开放问题、方法收束。

同类案例要变化叙事视角。可优先选择客户转型、内部阻力、组织政治、实施摩擦、管理决策或利益冲突，避免重复“发现需求—升级方案—赢得大单”的单一路径。

## 中文口播

- 使用自然口语和短句，一句表达一个完整想法。
- 避免原始英文词混入中文句子；产品名、公司名、固定术语和关键原话除外。
- 避免 `不是……而是……` 及近似结构，改成直接判断、因果关系或两个短句。
- 每个空行分隔的段落保持一个声音；不要为了换声把同一完整意思拆开。
- 人类可读的 `narration.txt`、屏幕字幕和归一化后的 TTS 文本中，`CEO`、`CIO`、`CRM` 等英文缩写保持连写，不在字母之间或缩写与相邻中文之间加空格。
- 屏幕字幕可保留便于识别的数字和缩写；口播文本仍需归一化数字、金额、日期和符号，但不再用字母间加空格的方式处理英文缩写。

## 时长预算

- 经验语速约为每分钟 330 个中文字符，包含自然停顿。
- 先通过旁白篇幅接近目标时长，再做小幅语速调整。
- 片头片尾约占 60 字，应从正文预算中扣除。
- 5–6 分钟通常能容纳完整案例弧线；强行把长材料压到 4 分钟会损失引用、升级节点和停顿空间。

## 写作检查

- 开头 20–30 秒内出现明确问题或风险。
- 每段承担一个叙事动作，不堆叠背景信息。
- 年份、金额、比例、区间在交给 TTS 前可被明确归一化；英文缩写默认保持连写。
- 每版旁白定稿前由大模型复核一次，重点检查口播自然度、禁用对比句式、源旁白缩写空格和数字读法风险。
- 结尾回到用户可带走的方法、判断或问题。
