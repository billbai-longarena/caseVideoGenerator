# 销售案例的客户真相线与销售认知线

## 目标

销售案例和销售管理案例在写正文或旁白前，先建立三层世界：

1. **客观真相层：** 客户的问题怎样积累、组织怎样决策、最终为什么选择某个方案。
2. **客户披露层：** 客户在不同信任和政治安全水平下，愿意向销售透露多少。
3. **销售认知层：** 销售从有限线索形成怎样的故事版本，其中哪些是事实、推断、误判和过时信息。

故事张力来自三层之间的信息差。结尾的意外结果必须能被客观真相层解释；回看前文时，读者应能找到已经出现过的线索。

## 生成模式与事实边界

- **来源约束模式 `source-grounded`：** 用于真实案例。事实、数字、事件和人物动机必须能追溯到材料；缺失信息写成 `unknown`，不能为补齐结构自行发明。
- **合成案例模式 `synthetic`：** 用于教学案例或情景演练。允许由参数生成角色、事件和结果，但必须保持行业常识、组织逻辑与因果一致。
- 真实材料需要合理化补全时，先把拟补内容列为假设并获得用户确认，再纳入模型。

## 三类竞争选项

客户最终只能在三类大选项中作出选择：

| 竞争类别 | 含义 | 常见形式 |
| --- | --- | --- |
| 外部供应商 | 选择我方或另一家外部公司 | 直接竞品、不同技术路线、顾问或服务商 |
| 客户内部方案 | 依靠现有组织和资源自行解决 | 自研、扩编、流程改造、跨部门调配、临时绕行 |
| 不采取行动 | 延期、维持现状或接受损失 | 不立项、缩小范围、等待预算、继续忍受问题 |

三类是一级竞争空间，每类可以包含多个具体候选项：

- 外部供应商：我方、竞品 A、竞品 B 或不同技术路线。
- 客户内部方案：自研、扩编、流程修补或沿用现有系统。
- 不采取行动：立即搁置、延至下个预算周期或缩小问题范围。

最终结果同时记录 `category` 和 `selectedOption`。例如客户选择竞品 A，一级类别是 `external_supplier`，具体选项是 `competitor_a`。

制度、利益冲突、风险、信任和个人偏好属于**决策力量**。它们改变三类选项的权重，不单独构成第四类竞争。

每个选项至少比较以下维度：

- 预期收益与问题解决程度
- 显性成本和隐性组织成本
- 实施风险、可逆性与责任归属
- 上线速度和错过窗口的代价
- 对现有权力、预算和岗位边界的影响
- 客户对执行者的能力信心与关系信任
- 关键参与者的组织目标、个人需求和偏好

销售即使领先所有外部竞品，也可能输给内部方案或“不采取行动”。案例必须明确真正赢得客户选择的是哪一类选项。

## 客户真相线

销售进入前的客户前史和决策底盘要独立生成。客户的问题、后果、组织关系和可选路径已经存在；销售进入后的信任、联盟、选项权重和最终结果由互动共同塑造，不能提前写死。

| 阶段 | 客户组织状态 | 必须回答的问题 |
| --- | --- | --- |
| 0. 容忍 | 问题存在，但被当作日常摩擦 | 谁最早感受到？为什么还能忍？ |
| 1. 积累 | 频率、范围或相互影响持续扩大 | 问题怎样从局部扩散？ |
| 2. 后果 | 形成可见损失、风险或机会成本 | 谁开始付出代价？证据是什么？ |
| 3. 触发 | 一个关键事件让继续容忍失去合理性 | 为什么偏偏现在必须改变？ |
| 4. 探索 | 内部和外部方案进入候选集 | 三类竞争选项各自凭什么成立？ |
| 5. 动员 | 预算、专业能力和决策参与者被拉入 | 谁参与？分别贡献什么判断？ |
| 6. 评估 | 标准形成，选项被试探、比较和重塑 | 公开标准和真实标准有何差距？ |
| 7. 承诺 | 组织承担选择带来的成本和责任 | 谁拍板？谁支持？谁接受代价？ |
| 8. 验证 | 实施结果反过来验证原判断 | 哪些结果证明选择有效或失误？ |

问题链至少包含：

```text
小困扰
→ 积累机制
→ 可衡量的损失或后果
→ 关键触发事件
→ 改变授权
→ 方案探索
→ 组织选择
```

触发事件负责让旧问题无法继续被忽略。它不能凭空创造需求，也不能充当天降解法。

## 客户决策网络

客户组织的决策由网络完成。每名参与者至少记录：

- 角色、正式权力和非正式影响力
- 在问题链中承受的后果
- 能提供的专业见解、资源或否决权
- 专业优势、经验来源、认知偏差和组织盲区
- 组织目标与考核责任
- 个人需求、职业风险和偏好
- 倾向的竞争选项及原因
- 能够披露哪些信息，披露会承担什么风险

同一参与者可以在不同阶段改变立场。人员离职、升迁、换岗或新领导到任会改变决策网络，也会让销售原有信息过时。

客户决策流程要同时记录两条路径：

- **正式流程：** 立项、预算、技术评估、采购、法务、安全、审批和签约等明文步骤。
- **实际流程：** 谁先定义问题、谁提前对齐、谁组织联盟、谁拥有隐性否决权，以及正式会议前结果是否已经基本形成。

每个决策阶段至少记录进入条件、负责人、参与者、所需证据、形成的输出和下一道门槛。参与者贡献可以是问题证据、业务价值、技术可行性、财务约束、政治合法性、实施能力或否决意见。最终决定不能只写成“老板拍板”，要解释老板依据谁提供的判断、承担什么风险、接受了哪些交换条件。

## 信任与信息逐级披露

客户不会一次性向销售展示完整组织结构。信息披露由信任、政治安全、角色权限和当前互动价值共同决定。

| 披露层级 | 常见信息 |
| --- | --- |
| L0 公开信息 | 官网、公开财报、招标参数、行业共识、对外统一口径 |
| L1 运营信息 | 实际流程、局部损失、使用问题、时间限制、已尝试方案 |
| L2 组织信息 | 决策流程、预算争夺、内部方案、部门冲突、隐藏反对者 |
| L3 战略与个人信息 | 真实意图、成败标准、个人风险、职业目标、未公开偏好 |

披露上限遵循：

```text
可披露深度 ≤ 信任水平、政治安全、角色权限、互动相关性中的最低值
```

因此，关系熟悉也不必然得到全部信息。对方可能信任销售，却没有权限透露；也可能掌握信息，却担心在组织政治中留下痕迹。

信任和披露是双边关系，不是客户公司的单一总分。同一客户角色可能只向新供应商讲 L0 公开信息，向长期合作的竞品分享 L2 组织信息，却只在个人安全得到保障后向某位销售透露 L3 个人需求。模型应按“客户角色 × 信息接收方”维护信任与披露状态。

每次披露都要有触发原因，例如销售提供了有价值的信息、兑现了承诺、保护了对方、提出了准确问题，或客户面临的后果继续扩大。

## 销售认知线

销售故事从一个不完整入口开始。先定义：

- 线索渠道：公开信息、转介绍、老关系、服务团队、合作伙伴、观察、偶然事件等
- 销售进入时客户所处的决策阶段
- 销售的动机、好奇心、潜意识态度和风险偏好
- 销售风格：产品型、关系型、顾问型、挑战型、流程型或混合型
- 优势：专业知识、倾听、提问、关系资本、商业判断、团队整合等
- 盲区：过早推销、单线关系、迷信历史经验、回避冲突、过度自信等
- 有意识动作与习惯性动作
- 销售团队各自掌握的信息、利益和功能偏见

销售及团队会形成自己的客户故事版本。每条判断必须标记为：

| 类型 | 定义 |
| --- | --- |
| 已验证事实 | 有来源或多方证据支持 |
| 客户表述 | 客户说过，但可能只代表某人或某个披露层级 |
| 合理推断 | 能被证据支持，仍需验证 |
| 未验证假设 | 暂时用于行动的猜测 |
| 过时信息 | 曾经正确，客户变化后已失效 |
| 未知 | 当前没有足够信息 |

销售不能因结局正确就被写成从一开始什么都知道。好的案例要展示他如何更新判断，也要保留那些没有被及时纠正的误判。

## 销售路径与风格

销售进入时先建立自己的**计划路径**，互动后再记录**实际路径**。常见计划路径是：

```text
线索获取
→ 资格判断
→ 初步问题假设
→ 关键参与者拓展
→ 共同定义问题
→ 方案塑形
→ 价值与风险验证
→ 组织承诺
```

具体案例可以跳过或回退某些阶段。回退必须由新信息、客户变化或销售失误触发。

销售风格决定默认动作和信息来源：

| 风格 | 默认动作 | 容易形成的故事版本 |
| --- | --- | --- |
| 产品型 | 早展示功能和差异 | 把问题理解为功能匹配，容易低估组织成本 |
| 关系型 | 依赖熟人和关键支持者 | 对单一角色理解深入，容易把个人口径当成组织共识 |
| 顾问型 | 提问、诊断并共同定义问题 | 能发现隐性需求，也可能分析过久、错过决策窗口 |
| 挑战型 | 用洞察重构客户问题 | 能打破现状惯性，也可能在信任不足时触发防御 |
| 流程型 | 建立参与者地图、验证点和共同计划 | 信息更新稳定，也可能忽略非正式政治和情绪信号 |

混合风格要指定主风格和压力下的退化风格。销售的优势、盲区和潜意识习惯决定他在哪些节点偏离计划路径，也决定他更容易采信、忽略或误读哪些线索。

销售团队可以拥有多个不同版本的客户故事。模型要记录谁持有什么判断、分歧怎样被处理，以及团队对客户输出的信息是否一致。

## 双线互动循环

每一次有效互动都按同一循环记录：

```text
销售动作
→ 客户依据角色、信任和政治处境进行解释
→ 客户披露、保留或试探
→ 销售与团队更新自己的故事版本
→ 三类竞争选项的权重发生变化
→ 客户决策阶段或双方关系进入下一状态
```

一场互动至少改变下列一项，否则应压缩或删除：

- 新增或推翻一条信息
- 信任水平或披露深度
- 某名参与者的立场
- 客户决策阶段
- 三类竞争选项中的相对权重
- 销售团队的共识或分歧
- 时间、预算、风险或政治成本

销售行动可以成功、失败或产生误导性反馈。客户也会试探供应商、控制信息、借外部方案推动内部议程。

每次关键互动建议记录：销售目标与动作、客户公开议程、客户真实用途、披露与保留的信息、双方各自解释、销售团队更新、竞争权重变化和下一状态。客户的真实用途可能是解决问题、学习方案、验证内部计划、建立预算依据、测试可信度、推动内部联盟或压价。

## 变化事件与黑天鹅

可用事件包括人员离职、领导更换、预算冻结、内部试点失败、竞品动作、监管变化、质量事故和外部市场冲击。

事件使用规则：

- 事件必须改变现有状态变量，不能只为制造热闹。
- 人员变化要同步更新信息权限、立场和销售关系价值。
- 黑天鹅负责加速、暴露或重新排序已有矛盾，不能直接替销售完成解题。
- 4–7 分钟案例通常使用 0–2 个重大变化事件；更多事件需要更长篇幅和更复杂的接力问题链。

## 初始参数

参数控制人物如何行动和认知，不直接替代故事事件。建议使用 1–5 等级，并为每个高低值写一句具体含义。

| 参数组 | 核心参数 |
| --- | --- |
| 生成控制 | `mode`、`variationSeed`、`complexity`、`eventBudget`、`targetOutcome` |
| 客户问题 | 严重度、积累速度、后果阈值、紧迫度、触发事件 |
| 客户组织 | 风险容忍、决策集中度、政治强度、现状惯性、披露谨慎度 |
| 客户参与者 | 问题暴露度、专业能力、正式权力、非正式影响、改变意愿、政治安全、披露权限、认知偏差、优势与盲区 |
| 竞争选项 | 三类初始吸引力、每类候选项、我方与直接竞品强弱、内部方案可行性、不行动吸引力 |
| 销售个体 | 好奇心、倾听、假设纪律、自信、耐心、政治敏感度、关系资本 |
| 销售团队 | 信息共享、跨部门协同、目标一致性、资源能力 |
| 环境 | 时间窗口、预算周期、人员变化、监管和黑天鹅概率 |

## 参数、状态与事件

三者必须分开：

- **参数**是较稳定的行为倾向，例如风险容忍、政治敏感度、好奇心和现状惯性。
- **状态**会随故事变化，例如问题严重度、客户决策阶段、关系信任、参与者立场、选项权重和销售判断置信度。
- **事件**是改变状态的动作或外部变化，例如一次访谈、内部试点失败、关键人离职或预算冻结。

每个参数都要写出低值和高值会产生的可观察行为，不能只贴性格标签。

| 参数 | 高值时的行为倾向 | 主要影响 |
| --- | --- | --- |
| `statusQuoInertia` | 即使损失出现，也要求更高证据和更安全的责任安排 | 不采取行动的权重、承诺阶段速度 |
| `disclosureCaution` | 先用公开口径试探，需多次兑现承诺才分享组织和个人信息 | 披露层级、信息获得速度 |
| `politicalIntensity` | 同一事实被不同部门解释为预算、权力或责任问题 | 参与者联盟、公开标准与真实标准差距 |
| `hypothesisDiscipline` | 主动区分事实和假设，并寻找反证 | 销售认知更新、误判持续时间 |
| `politicalSensitivity` | 识别沉默者、否决权和信息披露风险 | 决策网络覆盖、单线关系风险 |
| `relationshipCapital` | 更快获得入口和初始信任，也可能过度依赖旧关系提供的过时信息 | 访问权限、信任起点、信息新鲜度 |
| `teamAlignment` | 对客户形成一致问题定义和验证计划 | 客户信任、销售团队故事版本的一致性 |

真实案例结果已知时，`targetOutcome` 使用 `source_outcome` 并忠实还原。合成案例默认使用 `emergent`。只有用户明确指定教学结局时，才把 `external_supplier`、`internal_alternative` 或 `no_action` 作为场景搜索条件；它不能命令角色做出不合逻辑的选择。参数无法支持指定结局时，应调整初始条件或报告冲突，不能在结尾强行翻转。

`variationSeed` 用于选择同样合理的角色组合、进入渠道和事件分支。分支一旦选定，状态变化必须可追溯。`complexity` 控制参与者、互动和支线数量；`eventBudget` 限制重大变化事件，二者都不能用来制造无因果的噪声。

## 状态账本

案例模型至少维护以下动态状态：

- 客户问题严重度、后果阈值和当前决策阶段
- 三类竞争及其具体候选项的可行性与相对吸引力
- 每名参与者的立场、影响力、责任风险和联盟关系
- 客户角色与我方成员、直接竞品等外部接收方之间的信任矩阵
- 各信息项的披露层级、持有人和披露条件
- 销售团队信念账本中的类型、置信度和新鲜度
- 剩余时间、预算、实施风险和政治成本

三类选项及其候选项使用“初始判断 + 变化记录”，不要只保存最后分数。每次变化至少记录阶段、事件、受影响选项、方向、原因和关键参与者。最终决定还要经过可行性门槛、正式授权和关键否决权检查；最高权重不等于自动成交。

信念账本中的一条关键判断建议包含：

```text
判断内容、持有人、类型、置信度、证据来源、反证、
最后更新时间、信息新鲜度、下一次验证动作
```

## 中间工件

- `case_inputs.json`：生成模式、来源边界和初始控制参数。新写、大幅重构、参数化或合成案例必需；完整批准原文的直接改写可选。
- `case_model.json`：客户真相线、披露线、销售认知线、互动记录、竞争权重、最终决策和揭示计划。新写或大幅重构的销售案例必需。
- `case_story.md`：把模型编织成人类可读故事。由 Agent 创作案例正文时必需。
- `narration.txt`：从已确认的故事模型和案例正文改写出的口播源。

`case_model.json` 是生成型案例的叙事事实源。它不替代 `narration.timeline.json` 的时间职责，也不替代 `rich_storyboard.json` 的画面职责。

推荐的顶层结构：

```text
meta
inputs
customerTruth
decisionNetwork
competition
disclosure
salesWorld
interactions
outcome
revealPlan
causalAudit
```

其中 `customerTruth` 同时记录销售进入前的客户前史，以及互动结束后才能确定的完整客观时间线；`salesWorld` 记录计划路径、实际路径、销售风格，以及销售和团队在各时点真正知道或相信的内容。

## 从模型到故事

1. 先生成销售进入前的客户前史、进入时的决策阶段和没有销售影响时的基准路径，不预写最终结果。
2. 建立三类竞争选项、决策网络和每人的组织需求、个人需求及披露权限。
3. 让销售从指定渠道和阶段进入，依据初始信息形成第一版客户故事。
4. 逐次模拟互动、披露、误判、验证和团队内部解释，并记录状态变化。
5. 加入有限的变化事件，重新计算关系、认知、联盟和选项权重。
6. 由客户组织逻辑、销售影响和环境共同得出最终选择，完成客观真相线。
7. 做因果和反事实检查，确认结果不依赖临时新增的巧合。
8. 最后设计读者的揭示顺序。读者可以先跟随销售的版本，再逐步看见客户真相。

读者跟随销售视角时，销售的猜测必须用“他判断”“团队当时认为”等认知框架表达，不能由全知旁白把猜测陈述成客观事实。后续揭示可以纠正人物判断，不能反过来否认旁白先前明确宣告的事实。

最终揭示需要同时回答：

- 客户的问题为什么在这个时点进入决策？
- 三类竞争选项为什么发生此消彼长？
- 哪些人怎样影响了决定？
- 客户为什么在那个时点披露那层信息？
- 销售哪些判断正确、哪些误判、哪些信息已经过时？
- 最终结果为什么在隐藏结构下具有必然性？

## 销售管理案例的映射

销售管理案例可以把“客户组织”替换为“作出管理选择的销售组织”，把“销售认知线”替换为“管理者或一线团队的认知线”。仍然保留三类选择：购买外部能力、内部解决、维持现状。

如果案例同时包含客户决策和销售组织决策，先确定哪一条决定最终结果。主线只选一条，另一条作为约束或镜像线，避免双主线争夺篇幅。

## 质量检查

- 客户问题是否经历了积累、后果和触发，而非突然出现？
- 三类竞争是否全部被考虑，各类中的具体候选项是否足以解释真实竞争，哪一类缺席是否有合理原因？
- 制度、利益、信任和个人偏好是否明确作用于某个选项？
- 销售进入时的客户决策阶段是否明确？
- 每名关键参与者是否贡献了不同判断，并拥有组织与个人层面的动机？
- 信息披露是否符合信任、政治安全、权限和相关性？
- 销售故事版本中是否区分事实、推断、假设、过时信息和未知？
- 每次关键互动是否改变了信息、关系、决策阶段或选项权重？
- 变化事件是否放大已有因果，而非充当天降解法？
- 最终决定是否能由前文结构推出？
- 揭示后能否解释此前所有重要异常和误判？
