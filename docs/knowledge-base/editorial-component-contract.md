# Editorial 画面：模型创意与程序组件分工规范

本文定义 schema-v2 `editorial` 画面的职责边界。目标是让模型承担真正需要判断的导演工作，同时把裁剪、材质、碰撞、时序和可读性变成可测试的程序合同。

## 职责矩阵

| 层级 | 必须负责 | 禁止负责 |
| --- | --- | --- |
| LLM 导演计划 | 叙事目的、Visual Beat、素材身份、人物与信息区的预留 `box`、文案、语义色、揭示 unit、镜头、转场、局部 chrome | 猜测图片像素裁剪、依靠 scene/beat 序号轮换组件、把缺失选择交给编译器补创意 |
| 编译器 | 校验 schema、解析 unit、复制明确字段、解析资产引用 | 发明布局、动效、配色、素材、卡片或裁剪 |
| 严格校验器 | 安全区、对比度、显式 box、人物/面板碰撞、容量、时序和素材合同 | 自动移动元素后假装通过 |
| Remotion | 像素级方框、`contain`/`cover` 机械适配、卡片材质、插值动画、chrome 层级、封面切换 | 改写事实、文案、人物身份、beat 含义或导演预留的构图关系 |
| 像素 QA | 用真实渲染帧验证首帧、切换帧、人物帧、密集信息帧和结尾 | 仅凭 JSON 或缩略接触表宣称无问题 |

总原则：模型决定“为什么这样构图”和“各元素占哪块区域”，程序决定“如何稳定、可读地画出来”。

## 1. 封面与正片衔接

- 封面是独占画面的短 splash，结束帧统一由 `coverEndFrame()` 计算，最长为 `COVER_MAX_SECONDS`。
- 封面存续期间，底层 scene 的 BrandBug、ChapterBadge、SubtitleBar 和正文图层不得穿透到封面之上；封面自己负责需要从第 0 帧出现的品牌角标。
- 封面标题退出后，正片从下一个语义状态进入。底层首个 beat 不再重复绘制同一句标题或问话，避免交叉淡化时形成重影。
- 转场可以共享背景和相机方向，但不能共享两套同时可读的标题层。

## 2. 文字卡合同

- 叙事文字必须放在有边界的表面上。女性领导力竖屏系列默认使用浅色字 `#FFF8E8`/`#F7E7C7`，配深色 `glass` 或 `solid` 背景框。
- 深色文字直接压在水彩背景上的 `surface: none` 不属于该系列的成片语言；它只可用于经过单独批准的装饰性、非关键信息。
- 正文卡片统一具备：C 档玻璃透明度（主层 80%，渐变次层 72%）、局部深色渐变、细描边、轻微内高光、硬投影与柔投影，以及主题色细条。组件质感由 Remotion 决定，模型只选择卡片语义和占位；封面卡、正文 glass 卡和比较卡共用同一默认材质。
- `paper`、`accent`、`solid` 等不透明表面必须有显式 `box`。与人物同拍的所有语义面板都必须有显式 `box`，不能只依赖 slot 的隐式坐标。

## 3. 人物头像合同

- 人物源图为 1024×1024、纯白背景、半身或胸像、中国人物；生成模型负责人物外观，不负责最终版式裁切。
- LLM 导演声明人物资产及其“预留区域” `box`。该区域表达人物应处于画面哪里、与文字形成什么关系。
- Remotion 在预留区域内按真实画布像素计算最大的正方形，居中放置人物框，并强制人物图 `fit: contain`。因此 9:16 画布上的归一化宽高无需由模型反推成视觉正方形。
- 人物框的白底、边框、阴影和内边距由组件统一控制；模型不得用不同 `crop` 值补偿某张头像。
- 严格校验要求人物 asset layer 有显式 `box`。人物框与同时存在的文字、数字、对比条、关系图或对话面板之间至少保留 `0.012` 的归一化间隙；校验失败时回到导演计划修改预留区域，渲染器不得偷偷挪位。

## 4. 构图与层叠合同

- 同一时段的语义面板必须同时满足时间不重叠或空间不重叠。slot 查重用于粗粒度约束，显式 box 碰撞用于像素构图约束。
- 画面层级固定为：背景与处理层 → 叙事资产 → 语义面板 → 注释 → 常驻 chrome → 字幕。局部组件不能自行提高到 chrome 之上。
- 人物、文字卡、对比条等可在时间上分步揭示，但揭示动画不能改变最终预留边界。
- 任何“看起来差不多”的自动 fallback 都不能覆盖 box 冲突。缺少空间时，应减少同拍信息或拆成下一 Visual Beat。

## 5. 女性领导力五色水彩主题

`women-leadership-five-color-watercolor` 使用以下语义路由：

- 品牌与负向结果：陶土红 `#CA4D2A`
- 正向结果：叶绿 `#59A55D`
- 中性证据：雾蓝 `#7D9DC6`
- 支持性强调：暖橙 `#ECA23F`
- 高光与细节：暖黄 `#EFDB56`

背景继续使用高明度奶油纸与五色水彩；正文组件使用深色承载面保证阅读。五色可以进入细条、进度条、图表和局部描边，不把正文卡片做成五块高饱和色板。

## 6. 开场钩子合同

- LLM 决定开场要制造的判断冲突、第一条证据和两到三个语义拍点。
- Remotion 负责数字计数、对比条长度、强调色、节奏曲线、卡片落位和微动；程序化动效必须服务证据变化，不能只是文字淡入。
- 第一拍给问题，第二拍立刻给可视化落差，第三拍只在有新事实时存在。封面已经说过的问题不在底层第一拍重复绘制。
- 开场常驻品牌从第 0 帧可见；竖屏不渲染 ChapterBadge，栏目名由 BrandBug 承担。

### 计数卡合同

- `value.from` 只定义数字动画的起点；`from: 0` 是普通计数动画，不得自动生成第二份“▲数值”。
- 需要展示前后差值时显式写 `showDelta: true`，并同时提供 `value.from`；只做单值计数时可省略 `showDelta` 或写 `false`。
- Remotion 必须读取计数卡实际 `box`/slot 像素尺寸，按可用宽度拟合主数值、前后缀和差值，不得仅按字符数量选字号。
- 主数值和差值保持单行；若在 42px 可读性下仍放不进预留区域，严格校验必须阻断，导演应扩大 `box`、缩短前后缀或拆拍。

## 7. 验收帧

每次修订至少检查：

1. 第 0 帧：完整标题、栏目角标、无底层字幕或正文穿透。
2. 封面结束前后各一帧：无标题/正片重影，视觉焦点连续。
3. 每个人物首次出现帧：头像为像素正方形、完整 `contain`、人物框与文字不碰撞。
4. 每个高密度 beat：浅字深框、层级清楚、没有面板互盖。
5. 最终 MP4：流、尺寸、帧率、音画时长、黑帧和发布副本均通过。
